# 5G Security Architecture Module

The 5G Security Architecture module teaches subscriber privacy (SUCI concealment), mutual authentication (5G-AKA), and SIM key provisioning, with a post-quantum migration focus. The lesson's profile details cite 3GPP TS 33.501 Rel-19 V19.7.0, where SUCI uses the null scheme or ECIES Profile A (X25519) and Profile B (P-256). The 3GPP specification record lists Rel-20 V20.3.0 as a later TS 33.501 version (checked 2026-11-18); verify its current text for deployment. The module distinguishes a research-proposal-based and workshop-specific Profile C implementation from adopted requirements. 3GPP TR 33.703 is under change control and a dedicated SUCI migration work item is PCG-approved; these are study milestones, not an adopted normative post-quantum SUCI profile.

## Key Concepts

- SUCI concealment: under a non-null protection scheme, conceals the subscriber-specific part of the SUPI before over-the-air transmission. The null scheme sends it without protection, and network-routing fields such as the home-network identifier and routing indicator are not concealed. See TS 33.501 Annex C and the linked, version-scoped source.
- Profile A (X25519): Curve25519 ECDH key agreement, 32-byte public keys, AES-128-CTR encryption, HMAC-SHA-256 integrity; quantum-vulnerable
- Profile B (P-256): NIST secp256r1 ECDH, ephemeral public key sent point-compressed (33 bytes) in the scheme output, AES-128-CTR encryption, HMAC-SHA-256 integrity; quantum-vulnerable
- Profile C (ML-KEM): not an adopted normative profile in the cited TS 33.501 V19.7.0. The research paper by Khan, Purification & Chang (_Information_ 2025, 16, 617) proposes the name and 0x3 identifier with Kyber-512 and leaves the KDF generic. Current 3GPP Rel-20 work is a study/work item; it is not an adopted implementation requirement. This playground uses ML-KEM-768 (1,184-byte public keys), AES-256-CTR, HMAC-SHA3-256 and ANSI X9.63 KDF, and adds a hybrid X25519 + ML-KEM mode. Those choices describe this project, not the paper or an adopted 3GPP TS profile.
- Profile C sample envelope PSC1 (project sample format, not a standard, not a TS 23.003 SUCI encoding): a 15-byte header, the 32-byte X25519 ephemeral key (hybrid only), the 1,088-byte ML-KEM-768 ciphertext, the encrypted MSIN and an 8-byte MAC over everything before it; 1,116 bytes pure and 1,148 bytes hybrid for a 9-digit MSIN. The home network recovers the SUPI from the received bytes and its own private keys alone, checking the MAC before decrypting. Profile A and B encodings are unchanged
- SUCI construction pipeline: retrieve HN public key from USIM, generate ephemeral key pair, compute shared secret (ECDH or KEM encapsulation), derive encryption and MAC keys via ANSI X9.63 KDF, encrypt MSIN with AES-CTR, compute HMAC tag, assemble SUCI structure
- 5G-AKA authentication: mutual authentication may use MILENAGE, an AES-128 example algorithm set. TS 35.206 defines f1/f1*, f2, f3, f4, f5/f5*: MAC-A, RES, CK, IK, and AK are outputs; the network derives its expected response from RES (5G-AKA derives RES*/XRES*). AES-128 and the 128-NEA/128-NIA air-interface algorithms are symmetric; Shor's algorithm does not break them, while Grover's algorithm affects generic key-search cost.
- 5G key hierarchy: CK and IK feed KAUSF, derived with HMAC-SHA-256 bound to the Serving Network Name; KAUSF yields KSEAF (the anchor key, passed to the serving network), KSEAF yields KAMF, and KNASint/KNASenc (NAS signalling) and KgNB (radio layer) are each derived from KAMF
- SIM provisioning supply chain: an illustrative K-generation and OPc-personalization flow, not a 3GPP-mandated architecture. GSMA PQ.03 says cryptographic key generation is often performed in an HSM and links between MNO and UICC vendor are often secured with TLS; it recommends assessing both. The project's sample computes OPc as AES_K(OP) XOR OP and locally protects an illustrative batch. It does not prove a production TRNG, HSM, card, transport, or subscriber database.
- Differential quantum vulnerability: the cited SUCI ECIES profiles use elliptic-curve key agreement, which is vulnerable to Shor's algorithm. ATIS recommends quantum-resistant key encapsulation for SUPI protection and optional hybrid support; this is a recommendation. MILENAGE/5G-AKA and the sample's AES protection are symmetric. GSMA PQ.03 v2.0 §5.5 describes MNO–UICC-vendor channels using TLS/IKEv2 and says to assess their key establishment and associated PKI for PQ migration; it does not say all provisioning links use those protocols.
- **Current standard and 3GPP migration status (observed 2026-11-18)** — The public ETSI PDF cited for TS 33.501 Rel-19 is V19.7.0. The 3GPP change-request page now lists a V19.7.0 version link; verify the latest specification text directly before implementation. The linked V19.7.0 edition defines the current null and ECIES SUCI schemes, not a post-quantum scheme. 3GPP TR 33.703 (Rel-20 study) is under change control. Work Item 1130028, "Post-quantum Cryptography Migration for SUCI," is PCG-approved for Rel-20 and has a scheduled end date of 2027-03-03. This is active study/work-item progress, not a published normative profile. ## Workshop Activities

- **Part 1 -- SUCI Deconcealment**: Step through the full 11-step SUCI construction and deconcealment process for Profile A (X25519), Profile B (P-256), and Profile C (ML-KEM), with real OpenSSL commands showing key generation, ECDH/KEM operations, KDF derivation, AES encryption, and HMAC computation
- **Part 2 -- 5G-AKA Authentication**: Run a local, fictional authentication sample: separate network and UE credential copies, RAND, MILENAGE, AUTN, KAUSF, XRES*, then UE MAC/AMF/next-sequence checks and serving-network and home-network response checks, with editable received values and a replay rejection. The sequence policy is an exact-next-sequence rule of this sample; it is not 3GPP conformance, NAS transport or a deployed session
- **Part 3 -- SIM Key Provisioning**: Walk through the secure SIM manufacturing supply chain from K generation and OPc computation through USIM personalization, encrypted transport, and an authenticated, validated in-memory sample import; card writing and subscriber database storage are walkthroughs only

## Related Standards

- 3GPP TS 33.501 (5G security architecture, incl. Annex C SUCI protection schemes), 3GPP TS 35.206 (MILENAGE algorithm), 3GPP TR 33.938 (3GPP Cryptographic Inventory — an inventory of the cryptography used in the 3GPP specifications for the 5G System in standalone mode, including ECIES, ECDH and RSA; it does not include resolution to PQC migration)
- 3GPP TS 23.003 (SUPI/SUCI identifier formats), 3GPP TS 31.102 (USIM application)
- FIPS 203 (ML-KEM), NIST SP 800-56C (KDF recommendations)
- RFC 7748 (X25519 Diffie-Hellman), ANSI X9.63 (Key Derivation Function)
