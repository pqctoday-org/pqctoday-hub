# Decommissioning & Program Closure — For the Curious

## What This Is About

Picture renovating a building: it's not enough to install the new locks — you also have to collect and destroy all the old keys, and then officially sign off that the project is finished and hand the keys to whoever runs the building day-to-day. This module is that final stage for a cryptography migration.

## Why It Matters

The riskiest moment is thinking you're done when you're not. Adding a post-quantum algorithm alongside the old one leaves the old, breakable cryptography still in place. Real completion means removing it — and _checking_ it's gone — guided by published deadlines (deprecate by 2030, disallow by 2035). And proof should come from watching the system actually behave the new way, not from a status report.

## The Key Takeaway

Two honest habits separate a finished program from a stalled one: verify by observation (and sample sensibly across a big estate so it's feasible), and close with named owners for everything that continues — the inventory, the monitoring, the vendor follow-ups — plus a written acceptance of any residual risk. That way nothing important is left orphaned.
